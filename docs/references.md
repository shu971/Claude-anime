## 1. @twoclipping「How I Make $10K Launch Videos for $0 with Opus 5.5」
https://x.com/twoclipping/status/2104446706741825818 （2026-09-28、22.8万表示）
**AI駆動塾の記事の元ネタ。プロンプト原文3本が載っている。いちばん重要。**

### 手順（6ステップ）
1. **参考動画から骨組みを借りる：** ffmpegで1秒2コマ抜いてコンタクトシートにし、拍ごとに「何が起きるか／場面のつながり／カメラ／色／フォント」を書き出させ、自分の商品に当てはめる。
2. **スタジオ化：** ffmpeg＋Playwright(Chromium)。2秒テスト＝黒丸がばねで横長ピルに伸びる、60fps。HTML 1枚に `seek(t)`。
3. **素材：** Mixkit（曲・効果音）、Pexels、Google Fonts。曲はnumpyで拍グリッドとドロップ時刻を測る。効果音は1イベント1つ、ピーク位置を測る。著者は「合成音は安っぽかった」と言っている。
4. **型の決まったプロンプト：** XMLタグで `<inputs>` `<direction>` `<structure>` `<build>` `<gotchas>` `<start>` の6部構成。
5. **高く見せる7か条：** フェードせず形が変わる／カットしない／1拍ごとに何か起きる／着地で少し弾む／カメラは一度に1動作／音は本物／見せる前に自己点検。
6. **仕上げ：** 60fps・モーションブラー・効果音合わせ・全コマ点検 → 監督目線のメモで2〜3往復。

### build（作り方）で共通する技術
- HTML 1枚。全スタイルを `seek(t)` 内で時刻から計算。CSSトランジション・タイマー・フレーム間の状態は禁止。
- カメラはコンテナ1つの transform。キー `[時刻, ズーム, x, y]`、ズームは**対数空間で補間**。
- ばねは**閉形式（ステップ応答）**。目標が何度も変わる値は「変化ごとのばねの和」にして、時刻だけの関数のまま保つ。
- タブの指示子は前端と後端を別々の硬さのばねにして、伸びて見えるようにする。
- ドラッグ中は値をカーソル位置から計算、離したらその位置からばねで戻る。
- 層の受け渡しは「共有要素」：色が広がるとき前の要素の文字を一緒に運ぶ。
- 書き出し：1コマを4〜8サブフレームで描き、ffmpeg `tmix` で重ねてモーションブラー。速い動きは4だと残像が分かれるので8にして動きを遅くする。
- 点検：1拍1コマで並べる／速い瞬間はコマ送り／**前後の3倍のフレーム差がある1コマの飛び**を機械的に探す。
- 音：-14 LUFS に loudnorm。

### gotchas（つまずき）
- 画面を満たす色の広がりは、いちばん遠い角まで覆い、約0.3〜0.35秒かける（短いとフラッシュに見える）。
- 全レイヤーに z-index。
- 折り返す文字カーソルをカメラで追わない（行は固定）。
- カメラで拡大する要素に `will-change` を付けない（文字がぼける）。
- 形が変わる箱の中で入れ替わる文字は、独自の出入りタイミング（とマスク）が要る。
- ループは最後のコマ＝最初のコマ（カーソル位置と速度も）。
- Chromiumでは `backdrop-filter: url()` が変位マップを誤読する → 背景を複製して使う。
- `python http.server` は動画のシークができない → blob URL で読む。実写素材は全キーフレーム化（`-g 1`）。

## 2. @0xMovez「How to build motion design studio with Opus 5.5（Full-course）」
https://x.com/0xMovez/status/2104216919033192746 （2026-09-27、412万表示）
**いちばん体系的。12ステップの講座＋実装コード付き。** 「プロンプトは1割、残り9割は仕組み（ハーネス）」という主張。

### 要点
- **01 仕組み：** モデルは動画でなくプログラムを書く。Opusは依存ゼロの「index.html＋seek＋Playwright＋ffmpeg」を好み、RemotionやHyperFramesがあっても使わないことが多い。使わせたいなら明示する。
- **02 環境：** Node・ffmpeg・Python(numpy/librosa)・Playwright。任意で Remotion スキル、HyperFrames スキル、手描き風の claude-animation-skill。プロジェクト直下に **CLAUDE.md（スタジオの家訓）** を置く：
  - 描画契約：純粋な時刻の関数、乱数は種付き（mulberry32）で Math.random 禁止、H.264 yuv420p CRF16。
  - 見た目の禁止：グラデ背景に中央タイトル、全部フェードイン、隅のラベルや枠、UIのグロー、ありがちな粒子。
  - 2〜4秒ごとに新しいことが起きる。
  - 音：曲が渡されなければ**コードで合成**。拍グリッド（beats.json）に置く。-14 LUFS。
  - 見せる前のループ：1拍1コマのシート → 6項目を10点満点で採点 → 下位3つを直す → 全部8点以上まで繰り返す。
- **03 一行プロンプト：** 「履歴書用のショーリールのように、すごいモーションデザイナーであることを見せる15秒の動画を、全力で」。ジャンルの暗黙ルールを使える。ただし皆同じ絵になる（brief contagion）。歴史を物語で見せる変形版（縦9:16、45秒）もある。
- **04 ブランド：** 商品URL、「実際の画面・ロゴ・素材を使う」「音楽必須」の3行を足すだけ（Tony Dinh）。同じブランドは同じセッションで続けると速い。
- **05 参考：** 「スタイルを名指し」するほうが「描写」より効く。参考動画 → style_guide.md（色hex・書体・ショット長・転換・カメラ・質感・文字の出入り）→ shotlist.md → OKを待つ。中身ではなく文法を借りる。
- **06 状態リスト：** twoclipping のXML型の汎用版テンプレ。
- **07 エンジン：** canvas＋`window.seek(t)`、SCENES配列に `{from,to,draw}`。レンダラは Playwright で `seek` → スクショ → ffmpeg に流す。`tmix=frames=SUB, select=…` でサブフレームを1コマに。
- **08 ばね：** 閉形式の減衰ばね関数、`track(t, keys)` で「変化ごとのばねの和」、前端と後端で硬さを変える指示子、箱の中の文字の出入りアルファ、ループ用の時刻折り返し。硬さの使い分け：UI＝きびきび、カード・カメラ＝標準、大きい文字・ロゴ＝重め、マスコット＝はっきり弾む。
- **09 音：** 曲があれば librosa で bpm・beats・downbeats（4拍ごと）・hits（オンセットのピーク）を JSON に。なければ同じタイムラインで合成（click/pop/thump/whoosh の例コード）。合成音で2分の映画を成立させた例もある。
- **10 長編の監督ブリーフ：** 一行のログライン／参考／道具とキー／キャラ設定／拍シート（最初2秒にフック、3〜5秒ごとに見せ場）／画面の文字／**工程ゲート（計画→リグ→静止画→アニマティック→本番→磨き→音→書き出し）**／採点ループ／納品物。章ごとにサブエージェントに分け、先に ANIMATION_GUIDE.md を書かせて画風を揃える。
- **11 自己点検：** ffmpeg で①2fpsのコンタクトシート ②速い動作の前後12コマの帯 ③幅360pxのスマホ想定 ④2回連続再生でループの継ぎ目 ⑤同じコマを2回書き出してハッシュ一致（決定性）。採点項目：フック／スマホでの読みやすさ／動きの質／変化の多さ／構図／ブランド／音の同期。探す不具合：入れ替え時の文字の重なり、滑るだけの動き、隅のラベル、ぼけた拡大文字、何も起きない拍、ループのカクつき。直したら**影響した秒だけ書き出し直す**。
- **12 展開：** レイアウト関数で書いて 9:16／1:1／16:9 を同じタイムラインから出す（切り抜きではなく配置し直す）。パイプラインを**スキル化**（例：motion-reel）。

## 今の制作方法との関係（メモ）
- 仕組み（時刻だけで1コマが決まる→ブラウザで撮影→ffmpeg）は、方式Aの `frameAt(t)` + render.mjs と同じ。土台はある。
- 新しく取り込めそうなもの：拍グリッド中心の設計、閉形式ばね＋「ばねの和」、対数ズームのカメラ、サブフレーム＋tmix のモーションブラー、60fps、1拍1コマ点検＋採点ループ、フレーム差による飛び検出、決定性チェック、CLAUDE.md の家訓、スキル化、複数比率の同時出力。
- 衝突する所：効果音は「本物を使え」（twoclipping）vs「合成で」（Movez、こちらはユーザーのルールと一致）。Playwright 導入は既存の puppeteer-core で代用可能。
